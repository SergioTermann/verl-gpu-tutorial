# 从博士研究训练到大模型工程实践

这套课程的目标是让你能独立提出假设、写出可审查的训练代码、解释失败并复现实验。读完教程不是能力证明；每个阶段都要留下代码、预测、配置和判断依据。你已有研究训练，可以略读基础概念，但不要跳过张量、数据和系统边界的验证。

## 先修知识：用问题检查，不凭学历跳过

1. 对 softmax 加交叉熵求导，解释为何无需显式构造 Jacobian。
2. 给定 `[B,T,V]` logits，写出回答 token 的 log-prob、EOS mask 和 padding mask，说明 shift 的方向。
3. 区分估计偏差、采样方差和训练种子变异；解释同题多回答为何相关。
4. 说明 AdamW 的权重衰减、优化器状态、梯度累积与 batch size 的关系。
5. 解释因果 attention mask、位置编码、prefill、decode 和 KV cache 的用途。

遇到不熟悉的概念时，先写一个十几行的小实验，验证形状或梯度，再回到整条训练流程。第 13 课提供了这种做法的样例。

## 建议学习顺序与验收

| 阶段 | 课程 | 必须交付的证据 | 口头答辩问题 |
|---|---|---|---|
| 计算与数据 | 01、02、05、06 | 设备计时、分组划分、完整预测 | 为什么训练准确率高不等于泛化？ |
| 学习目标 | 03、04、08、13 | 梯度检查、奖励攻击样例、冻结/SFT/RL 对照 | 一组全对为何也没有相对优势？ |
| 工程可靠性 | 09、10、11 | 恢复误差、接口检查、权重与状态变化 | loss=0 时如何判断更新是否发生？ |
| 从失败到假设 | 12、14 | 冷启动与预热结果、失败日志、实验 manifest | 哪个证据支持格式问题，哪个支持任务学习？ |
| 评估与系统 | 15、16 | 配对区间、分层报告、资源预算与实测 | 哪项结论超出了现有实验的证据？ |
| 预训练模型交付 | 17、18 | 适配器一致性、合并误差、HTTP 逐请求指标 | FP32 合并正确为何不保证 BF16 服务逐位相同？ |

建议按阶段完成，每次学习先预测现象，再运行，再解释反例。你可以快读，但验收不能只看单元格是否变成绿色。

## 实验卡：开跑前填写

将下列内容保存到每次运行目录，训练结束后追加结果，不覆盖原计划。

```text
问题：什么现象需要解释？
假设：哪个机制会导致这个现象？什么结果会推翻它？
主指标：定义、分母、输出解析、EOS/截断处理。
数据：来源、版本、分组单位、重复检查、train/val/test 哈希。
对照：同一起点的冻结、继续 SFT、RL；哪些条件保持一致？
预算：GPU 时间、生成 token、更新次数、监督标签使用量。
配置：代码 commit、依赖版本、模型/tokenizer、随机种子。
停止：固定预算或验证集条件；最终测试何时查看？
失败判据：OOM、NaN、无有效组、协议失败、质量回退。
结果：全部种子、失败尝试、逐题预测、置信区间、资源指标。
结论边界：哪些因素仍然混杂？下一项最小消融是什么？
```

## 大模型岗位还需要补上的四个项目

下面列出项目验收要求。17/18 已提供预训练小模型 LoRA 与本地服务的起步实验，但没有完成全部对照和生产验收。每个后续项目仍需先确定硬件、模型许可、数据来源与任务。

### A. 预训练模型上的 SFT 与 LoRA

从第 17 课开始：Qwen2.5-0.5B-Instruct、合成工单路由、模板分组划分、单批损失检查、LoRA 保存重载、BF16/FP32 合并诊断。当前未做全量微调对照和多种子实验。

选一个能在设备上运行的预训练模型，固定 chat template、padding、截断与回答掩码。先验证单批过拟合，再比较冻结、LoRA 与可承受的全量微调。记录可训练参数、实际 optimizer state dtype、峰值显存和生成质量。检查 LoRA 保存/加载前后的输出，并验证合并权重后数值差异。

数据不能只靠随机行切分。按文档或用户分组，检查近重复、答案泄漏、模板变化与训练分布外样本。每个预处理决定都要写入数据版本。

### B. 偏好优化与可验证奖励

先区分“有正确答案的可验证任务”和“只有偏好比较的任务”。前者可用规则奖励，后者需定义偏好采集、标注一致性与奖励模型的局限。

推导 DPO 的 chosen/rejected log-prob 比值，比较它与在线 RL 的数据来源、reference 依赖和探索成本。实现 chosen/rejected 对调、长度偏差、重复答案与格式漏洞检查。不要把 DPO 等同于“不需要参考策略”，也不要用奖励模型分数本身代替最终任务评估。

### C. 多卡与中断恢复

在有多卡资源时，分别测单卡与数据并行/FSDP 配置。明确 world size、全局 batch、micro batch、梯度累积和采样数如何共同决定实际工作量。GRPO 中提示数与回答序列数要分开记录。

人为中断作业并恢复，检查模型、优化器、调度器、随机状态、数据位置与 step 是否一致。记录通信时间和扩展效率。第 11 课单卡 NO_SHARD 的成功不验证分片保存、跨 rank 随机状态或多机网络。

### D. 推理服务与回归评估

第 18 课已提供仅监听本机的临时 vLLM 服务、闭环并发 1/2/4、流式指标和答案回归。它使用短合成请求，不能代表开放到达率、长上下文或真实业务负载。

固定模型版本、量化配置和解码协议，构造真实长度分布的请求。分别测 TTFT、TPOT、吞吐、并发下 p50/p95 与错误率，记录 warm-up、排队和超时。比较连续批处理及不同并发上限时的质量与资源变化。

部署前保留离线回归集、线上观测指标和回滚阈值。模型版本、tokenizer、chat template 与服务参数应作为整体发布。对用户数据建立访问、保留与脱敏规则；这属于实际业务设计，不能靠教程中的合成数据实验代替。

## 最终工程考核

选择一个边界清晰的任务，完成一个可复现的小项目。评分按证据，而不是模型规模：

- 20%：数据与评估。无分组泄漏，有完整预测和合理的最终留出设计。
- 25%：目标与实现。能解释损失、mask、概率比率、KL 与实际梯度。
- 20%：实验设计。冻结/监督/奖励对照，至少三个种子，预算差异可追溯。
- 20%：系统与恢复。资源测量可信，故障有日志，checkpoint 能正确恢复。
- 15%：报告。明确失败与结论边界，另一位工程师能从 README 复现。

通过标准：报告中的每个主要结论都能指向具体配置和输出；面对一次失败，能够提出最小可验证修改，而不是无目标地加大模型、步数或显卡。
